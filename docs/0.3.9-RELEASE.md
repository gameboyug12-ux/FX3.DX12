# FX3.DX12 0.3.9 — Release integration

## Build products

The build produces static and dynamic engine variants, `main.exe`, native Win32
`FX3Editor.exe`, and raster/legacy-DXR/hybrid-DXR shader libraries. Dynamic linking
copies the engine DLL beside both executables.

## Editor

The primary editor is `editor/win32`: scene outliner, object properties/transforms,
console, status bar, scene new/open/save, add/delete, dirty-state prompts,
versioned `.fx3scene` serialization and D3D12 viewport. The modular 0.4 suite in the
uploaded source is a UI prototype, not the primary scene editor. The current viewport
still renders built-in preview geometry; scene documents are not automatically turned
into BLAS/TLAS instances.

## Hybrid DXR

- `hybrid_pathtrace.dxil`: standalone multi-bounce path tracing, shadows, rough/
  metallic reflections and diffuse GI.
- `hybrid_deferred.dxil`: raster-primary deferred hybrid pass. It consumes the five
  `DX12GBuffer` color targets and depth, then uses DXR for shadows, reflections and
  diffuse indirect lighting.

Use `DX12RaytracingApi::CreatePipeline(path, 5)` for `hybrid_pathtrace` and
`CreatePipeline(path, 12)` for `hybrid_deferred`. The descriptor order and
buffer formats are documented in `RT_DESCRIPTOR_LAYOUT.md`.

The deferred pass is an engine-facing pipeline. A host renderer must populate the
G-buffer, descriptor tables, BLAS/TLAS, frame data and output texture and synchronize
resource states/fences. The current editor viewport is not yet wired to this pass.
Temporal accumulation, denoising, automatic scene-to-AS building and render-graph
integration remain future work.

## Fixed-resolution spatial upscaling

The renderer now renders into a fixed-size off-screen target and runs a full-screen
linear-clamp sampling pass into the swap-chain. The automatic policy selects 720p
rendering for outputs up to 1080p, 1080p rendering for outputs up to 1440p, and
1440p rendering for larger outputs. The C application descriptor exposes fixed
720p, 900p, 1080p and 1440p render modes. This is a spatial fallback/scaler, not
AMD FSR 3 temporal upscaling. See docs/UPSCALING_RESOLUTIONS.md.

## AMD FSR 3 runtime

The optional FSR3 runtime loader header is in `include/XWe/Rendering/Upscaling` and
`src/rendering/upscaling`. It loads the supplied x64 effect/backend DLLs from
`<exe-dir>/third_party/FSR` and validates their exported entry points. Set
`FX3_FSR3_DLL_DIR` at CMake configure time to deploy those DLLs beside the runtime
and editor executables.

This release does not yet dispatch FSR3 GPU work or present interpolated frames.
The legacy FSR3 API requires exact SDK-matched context structures and callbacks;
the loader intentionally avoids calling function pointers with unverified ABI
declarations. See `docs/FSR3_RUNTIME.md` for the current integration boundary.

## Verification

Requires Windows 10/11 SDK, MSVC C++20, CMake 3.24+ and DXC with Shader Model 6.3 /
DXR library support.

```powershell
cmake -S . -B build-fx3 -G Ninja -DCMAKE_BUILD_TYPE=Release -DCMAKE_CXX_COMPILER="C:/Program Files/LLVM/bin/clang++.exe" -DCMAKE_CXX_FLAGS="-fuse-ld=lld" -DDXC_EXECUTABLE="C:/XWe0.2/cmp-utils/dx/dxc.exe" -DFX3_ENABLE_FSR3=ON
cmake --build build-fx3 --target XWeShaders xwe_engine_shared xwe_engine_static FX3DX12 FX3Editor
```

The fixed-resolution render-target and spatial scaling changes have not yet been
built or GPU-tested on Windows. Run the commands above and verify the DXC shaders,
MSVC/Clang compilation, resize behavior, output aspect ratio and frame pacing before
treating this as a stable release. DXR state-object creation and GPU rendering also
require a DXR-capable adapter.
