# XWe 0.3.6 — DX12 object model and raytracing API

## Public namespace and headers

All new DX12 types are declared in `XWe::DX::DX12`. Each requested object
has its own public header under `include/XWe/DX/DX12`:

| Requested public type | Header |
|---|---|
| `DX12Ctx` | `DX12Ctx.hpp` |
| `DX12PiplineStateObject` | `DX12PiplineStateObject.hpp` |
| `DX12RendererStateObject` | `DX12RendererStateObject.hpp` |
| `DX12RendererApi` | `DX12RendererApi.hpp` |
| `DX12GBuffer` | `DX12GBuffer.hpp` |
| `DX12Texture` | `DX12Texture.hpp` |
| `DX12Materail` | `DX12Materail.hpp` |
| `DX12Shader` | `DX12Shader.hpp` |

The specified spellings remain supported. Correctly spelled aliases
`DX12PipelineStateObject` and `DX12Material` are also available.
`DX12.hpp` is the umbrella include.

## Object responsibilities

- **DX12Ctx** owns references to the D3D12 device and direct queue, one command
  allocator/list, a fence and an event. Its single-allocator frame path waits
  for the previous submission before reusing the allocator.
- **DX12PiplineStateObject** creates graphics, compute and pipeline-state-stream
  PSOs and owns the resulting COM object.
- **DX12RendererStateObject** validates/stores render-target formats, depth
  format, sample description, viewport and scissor.
- **DX12RendererApi** provides begin/end frame, graphics PSO creation and
  raytracing initialization/pipeline creation.
- **DX12Texture** creates 2D committed resources, creates SRV/RTV/DSV/UAV
  descriptors into caller-owned heaps, and records explicit state transitions.
- **DX12GBuffer** creates Albedo, Normal, Material, Velocity and Emissive
  render targets plus a D32 depth texture; it can create RTV/DSV/SRV views (five color SRVs plus depth) and
  transition the color targets between render-target and shader-read states.
- **DX12Shader** loads DXIL/DXBC bytecode or accepts bytecode from memory.
- **DX12Materail** holds shared shader and texture references.

Descriptor heaps and descriptor allocation remain caller-owned. Texture view
methods write into handles supplied by the caller; they do not allocate heap
slots or manage descriptor lifetime.

## Raytracing API

Separate RT headers:
- `DX12RaytracingApi.hpp`: checks `ID3D12Device5` support and creates a
  raytracing state object from a DXIL library.
- `DX12AccelerationStructure.hpp`: builds BLAS from geometry descriptors and
  TLAS from instance descriptors, allocating result and scratch resources.
- `DX12ShaderBindingTable.hpp`: creates aligned ray-generation, miss and hit
  records from state-object shader identifiers.
- `DX12RaytracingDispatch.hpp`: binds the global root signature, shader-visible
  descriptor heap, Scene SRV table and Output UAV table, then records
  `DispatchRays`.

The minimal `shaders/pathtrace.hlsl` library exports `RayGen`, `Miss`,
`ClosestHit` and writes the ray result into `Output : register(u0)`; it
reads a TLAS from `Scene : register(t0)`.

### Intended use sequence

1. Create the D3D12 device and direct queue. Initialize `DX12Ctx`, create its
   command objects and call `QueryRaytracingCommandList()` to obtain
   `ID3D12GraphicsCommandList4`.
2. Initialize `DX12RaytracingApi` and create the raytracing pipeline from
   `pathtrace.dxil`.
3. Create vertex/index resources and fill `D3D12_RAYTRACING_GEOMETRY_DESC`.
4. Record `BuildBottomLevel`; populate `D3D12_RAYTRACING_INSTANCE_DESC`
   with the BLAS GPU virtual address and record `BuildTopLevel`.
5. Create a shader-visible CBV/SRV/UAV heap. Create a TLAS SRV for register
   `t0` and an output texture UAV for register `u0`.
6. Create the SBT with shader exports `RayGen`, `Miss` and
   `TriangleHitGroup`.
7. Transition the output texture to UAV state, call the dispatch API with the
   descriptor tables and SBT dispatch description, then transition output
   to a state suitable for sampling/presentation.

Example API shape:

```cpp
using namespace XWe::DX::DX12;

DX12RaytracingApi rt;
if (SUCCEEDED(rt.Initialize(device)) &&
    SUCCEEDED(rt.CreatePipeline(L"shaders/pathtrace.dxil"))) {
    DX12AccelerationStructure blas;
    // Fill geometry descriptors with valid GPU vertex/index addresses.
    blas.BuildBottomLevel(rt.Device(), commandList4, geometryDescs, geometryCount);

    // Fill instances with BLAS addresses, transforms and instance masks.
    DX12AccelerationStructure tlas;
    tlas.BuildTopLevel(rt.Device(), commandList4, instances, instanceCount);

    DX12ShaderBindingTable sbt;
    sbt.Create(device, rt.PipelineProperties(),
               L"RayGen", L"Miss", L"TriangleHitGroup");

    // Create shader-visible descriptor heap and TLAS SRV / output UAV first.
    DX12RaytracingDispatch dispatch;
    dispatch.Dispatch(commandList4, rt.Pipeline(), rt.GlobalRootSignature(),
                      shaderVisibleHeap, sceneSrvGpu, outputUavGpu,
                      sbt.DispatchDescription(width, height));
}
```

The snippet illustrates the intended API flow; callers can obtain the RT list via
`context.RaytracingCommandList()` after a successful query. Callers must check every
HRESULT, populate valid geometry/instance descriptors, create the TLAS SRV and
output UAV descriptors, and submit/synchronize the command list.

## Important constraints in 0.3.6

- Raytracing requires DXR-capable hardware and a device exposing
  `ID3D12Device5`; dispatch requires `ID3D12GraphicsCommandList4`.
- BLAS/TLAS build methods record commands; they do not submit the command list.
  Keep geometry resources alive until the build completes. Keep AS result,
  scratch, TLAS instance upload, shader table, output and descriptor heap alive
  until all GPU work using them completes.
- The acceleration-structure helper retains one result and scratch allocation
  per instance; rebuilding the same object replaces its resources. Do not
  rebuild while earlier commands using those resources are still in flight.
- The SBT helper currently writes one record for each raygen/miss/hit section;
  local-root-argument records and multiple hit records are future extensions.
- The renderer API uses a single allocator/list and waits for the prior
  submission before reuse. It is a safe starter path, not a multi-frame
  in-flight renderer.
- GBuffer creation currently provides render-target textures and a depth
  texture. Callers own descriptor heaps, RTV binding, pass setup and state
  tracking. The GBuffer does not yet implement a full deferred lighting pass.
- DXR pipeline setup is a starter pipeline contract, not a complete path tracer:
  no multi-bounce integration, accumulation, denoising, material hit shaders,
  reflection/refraction system, or final tone-mapping pass.
- Existing raster engine path remains the default runtime. The new public
  renderer/RT objects are available to integrate into the engine and game
  renderer; the current sample cube does not automatically invoke DispatchRays.

## Build

CMake project version and native `XWeGetVersion()` are `0.3.6`.
The build registers all new DX12 source files and compiles the DXR library
with DXC `lib_6_3`.

```powershell
cmake -S . -B build -A x64
cmake --build build --config Debug
```

A Windows SDK with D3D12 raytracing declarations and a compatible DXC are
required. Hardware support is checked at runtime, not assumed at build time.
