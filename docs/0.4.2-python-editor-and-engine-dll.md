# FX3.DX12 0.4.2 — PySide6 editor and engine DLL

This branch uses a Python-first editor workflow and a native engine DLL. The
only native application artifact intended by this workflow is
`xwe_engine.dll`; the standalone renderer target is disabled by the supplied
build script. No native C++ editor target is included in this branch's editor
directory.

## Repository layout

- `editor/pyside6/fx3_editor.py` — PySide6 scene/document editor.
- `editor/pyside6/requirements.txt` — optional GUI dependency.
- `include/XWeApplication.h` — stable exported C ABI declarations.
- `src/xwe_application.cpp` — DLL exports and engine lifecycle bridge.
- `engine/build_engine_dll.ps1` — invokes the existing CMake project with
  `FX3_BUILD_RENDERER=OFF` and `XWE_BUILD_ENGINE=ON`; it does not edit
  `CMakeLists.txt`.
- `tests/python/engine_dll_test.py` — Python ctypes smoke test and engine
  window launcher.

## Build the DLL (Windows x64)

Requirements: Windows 10/11 x64, Visual Studio 2022 C++ workload, Windows SDK,
CMake 3.24+, and the DirectX shader compiler dependencies required by the
existing engine project.

From a Visual Studio Developer PowerShell at the repository root:

```powershell
.\engine\build_engine_dll.ps1 -Configuration Release
```

Expected DLL:
`build-engine/bin/Release/xwe_engine.dll`

The script configures a separate `build-engine` directory. It does not
modify the root CMake file or create a standalone renderer executable.

## Test the DLL from Python

Smoke test loads the DLL, calls `XWeGetVersion`, creates an application
instance, and destroys it:

```powershell
py -3 tests/python/engine_dll_test.py --smoke
```

To provide an explicit DLL path:

```powershell
py -3 tests/python/engine_dll_test.py --dll build-engine/bin/Release/xwe_engine.dll --smoke
```

To run the engine's native Win32/D3D12 application loop:

```powershell
py -3 tests/python/engine_dll_test.py --run
```

The Python test uses `ctypes.WinDLL` and the exported C functions
`XWeGetVersion`, `XWeCreateApplication`, `XWeRunApplication`, and
`XWeDestroyApplication`. It is a real ABI-level call, not a mock.

## Run the PySide6 editor

```powershell
py -3 -m pip install -r editor/pyside6/requirements.txt
py -3 editor/pyside6/fx3_editor.py
```

The editor's **Engine → Run Engine DLL Test** command launches the Python
DLL test program with `--run`. The DLL owns its own Win32 window; the current
C ABI does not expose a render-surface handle for embedding D3D12 output into
a Qt widget. The editor's central panel therefore remains a scene-document
preview, not a live engine viewport.

## Scope and validation

This branch removes the Tkinter, native Win32 editor and C++/Qt editor
front-ends from `editor/`; PySide6 is the single editor UI. Engine
implementation sources remain C++ behind the DLL boundary. The DLL build and
runtime test must be run on Windows x64; they were not executed in the
current environment. Do not treat the DLL as prebuilt or claim a successful
Windows build until the supplied script and Python smoke test pass locally.
