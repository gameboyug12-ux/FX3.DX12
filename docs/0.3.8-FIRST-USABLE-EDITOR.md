# FX3.DX12 0.3.8 — First usable editor workflow

## Release scope

0.3.8 is a practical 0.3.x milestone, not a 0.4, 0.7 or 1.0 release.
It adds a first usable scene-authoring workflow to the separate Qt editor while
retaining the existing native Direct3D 12 engine and DXR preview.

## Editor features

- Separate `FX3Editor.exe`; the editor remains independent from `main.exe`.
- New, Open, Save and Save As for `.fx3scene` files.
- Versioned JSON scene document format (`FX3Scene`, schema version 1).
- Scene Outliner with selection, triangle-object creation and deletion.
- Properties panel for object name, type, location, rotation and scale.
- Dirty-state indicator, unsaved-change confirmation and console messages.
- F11 fullscreen toggle.
- Starter scene: `examples/BasicScene.fx3scene`.

## Scene file format

A scene is UTF-8 JSON with a root object containing:

- `format`: exactly `FX3Scene`.
- `version`: currently `1`.
- `objects`: array of objects with unique `id`, `name`, `type`,
  and three-component `position`, `rotation`, and `scale` arrays.

Writes use `QSaveFile` so an interrupted save does not partially overwrite
the destination file. Loading validates the format, version, object IDs and
transform vectors before replacing the currently open scene.

## Rendering status and limitations

The editor's DXR viewport remains the 0.3.7 hardware ray-tracing validation
scene: a single hard-coded triangle dispatched through BLAS/TLAS and a DXR
state object. Scene document transforms are editable and persisted, but they
are not yet bound to runtime mesh instances or acceleration-structure rebuilds.
Adding a scene object currently adds it to the scene document and Outliner; it
does not generate new GPU geometry in the preview.

This release does not claim production path tracing, mesh import, dynamic
scene rendering, camera navigation, material authoring, multi-bounce lighting,
accumulation, denoising, FSR integration or a complete game-engine toolchain.

## Build requirements

- Windows 10/11 x64.
- Visual Studio 2022 with C++ desktop workload and Windows 10/11 SDK.
- CMake 3.24 or newer.
- DirectX Shader Compiler (`dxc.exe`) available on PATH.
- Qt 6.5+ Widgets built for MSVC 2022 x64.
- DXR-capable GPU and current driver for the ray-tracing viewport.

Configure and build:

```powershell
cmake -S . -B build -A x64 -DCMAKE_PREFIX_PATH="C:/Qt/6.x.x/msvc2022_64"
cmake --build build --config Release
```

With the Visual Studio multi-configuration generator, Release executables are
emitted under `build/bin/Release/`: `FX3Editor.exe`, `main.exe` and
`xwe_engine.dll`; compiled shaders are under `build/bin/Release/shaders/`.

No Windows build or runtime test is claimed until the branch is compiled and
run on a Windows system with the required Qt/MSVC/DXC toolchain and DXR GPU.
