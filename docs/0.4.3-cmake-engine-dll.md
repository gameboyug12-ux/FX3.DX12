# FX3.DX12 0.4.3 — Engine DLL build

The 0.4.3 default CMake build produces the XWe engine DLL and its required
DXR shader library. The standalone FX3 renderer target is optional and OFF
by default.

## Requirements

- Windows 10/11 x64
- Visual Studio 2022 with Desktop C++ workload and Windows SDK
- CMake 3.24+
- DirectX Shader Compiler (`dxc.exe`)
- A DXR-capable GPU for the DXR runtime path

## Configure and build

From a Visual Studio Developer PowerShell:

```powershell
cmake -S . -B build -A x64 -DXWE_BUILD_ENGINE=ON -DFX3_BUILD_RENDERER=OFF
cmake --build build --config Release --target xwe_engine
```

If DXC is not on PATH, pass its full path:

```powershell
cmake -S . -B build -A x64 -DXC_EXECUTABLE="C:/Tools/DirectXShaderCompiler/bin/x64/dxc.exe"
```

The engine target compiles `shaders/pathtrace.hlsl` as a DXIL library
(`lib_6_3`) and writes it beside the DLL under
`build/bin/Release/shaders/pathtrace.dxil`.

The DLL is written to `build/bin/Release/xwe_engine.dll`.

## CMake corrections in 0.4.3

- The project version is 0.4.3.
- `xwe_engine` is created before target-specific link settings are applied.
- Engine sources are listed explicitly; the standalone renderer's
  `src/main.cpp` and renderer implementation are not accidentally globbed
  into the DLL.
- `UpscalingSettings.cpp` is not listed because upscaling settings are
  implemented inline in the public header in this source tree.
- DXC is discovered through PATH / a hint or supplied explicitly through
  `DXC_EXECUTABLE`; no hard-coded machine-specific executable command is
  required.
- Shader compilation is an actual build dependency, not a malformed
  `add_custom_command(TARGET ...)` call. HLSL include files are not compiled
  as independent shader entry points.
- The default build does not build the standalone renderer executable.
