# FX3.DX12 0.3.2

## Editor

The PySide6 editor launches fullscreen by default. F11 toggles fullscreen/windowed mode. It contains:
- Scene hierarchy
- OBJ import and OpenGL preview
- Object Inspector with editable position, rotation and scale
- C++ source tabs with basic C++17 syntax highlighting
- Open/save source file actions
- Output log and engine process launch (F5)

The current Object Inspector edits the preview object's transform. It is not yet a serialized engine scene object system. The viewport is still OpenGL-owned and not embedded from the native D3D12 renderer.

## Run

```powershell
py -3 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r editor\requirements.txt
python editor\main.py
```

## C++17 code editor

Use File > Open C++ source, New C++ tab, and Save code. The editor provides lexical syntax coloring; it does not yet provide compiler diagnostics, IntelliSense, project generation or build integration.

## XWeApplication DLL interface

The native target is built as `xwe_engine.dll`. Public header: `include/XWeApplication.h`.

Exported C ABI:
- `XWeCreateApplication(desc)`
- `XWeRunApplication(handle)`
- `XWeDestroyApplication(handle)`
- `XWeGetVersion()`

The standalone `main.exe` uses these same exports. A game can link to the generated import library `xwe_engine.lib` and deploy the DLL next to its executable.

## FSR 3.1, AA and Frame Generation

`include/fx3/render_features.hpp` defines configuration enums for AA, FSR 3.1 upscaling presets and frame generation. This is an API/configuration contract, not an active implementation.

A real FSR 3.1 implementation still needs the AMD FidelityFX SDK and native D3D12 integration for color/depth resources, motion vectors, camera jitter, exposure, reactive/transparency masks as required by the SDK path, FSR dispatch, and correct frame-generation present/frame pacing.

Until those pieces are connected and validated, the editor labels these modes as pending. Selecting a preset does not enable FSR.
